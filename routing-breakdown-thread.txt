Here's the problem I hit and how I fixed it:

---

1/ THE PROBLEM

OpenClaw kept hitting rate limits.

"Request too large for gpt-4o: Limit 30000, Requested 98358"

Large tasks (building HTML pages, complex code) were failing.

I was losing hours retrying failed requests.

---

2/ THE ROUTING BREAKDOWN

Built emergency routing that checks task size FIRST:

>100k tokens → Claude Sonnet (200k context)
  Cost: $3/1M tokens
  Why: Absolute reliability for massive tasks

30k-100k tokens → o3-mini (200k context, 100k output)
  Cost: $1.10/1M tokens  
  Why: 3x cheaper than Sonnet, huge output capacity

<30k tokens → Smart routing (Haiku/o3-mini/Ollama)
  Cost: $0-0.80/1M tokens
  Why: Cheapest capable model for the job

---

3/ THE MATH

Before: GPT-4o ($2.50/1M) × failed attempts = $$$ wasted

After:
• 50k token task → o3-mini ($0.055 vs $0.125)
• Large coding tasks → 60% cost reduction
• Zero rate limit errors

Monthly savings: ~$50-75

4/ HOW I DID IT (NO CS DEGREE)

Step 1: Read OpenClaw's entry point

Step 3: Added token estimation (chars ÷ 4)
Step 4: Hard-coded emergency rules at the TOP
Step 5: Tested, broke, fixed, deployed
