## ⚠️ LESSON: Astro slot content is NOT markdown-rendered (2026-08-09 12:43)
- Problem: Pit Row blog posts rendered as "one long run-on sentence" — raw markdown (##, **, -) showing through as literal text.
- Root cause: In `.astro` files, content inside `<Component>...</Component>` is the slot and renders as raw HTML — Astro does NOT render Markdown inside component slots. I had written posts in markdown format, which showed up as literal ## ** - characters.
- Fix: Converted markdown → HTML using `marked` (available in pitrowmiami-v2 node_modules). Wrote a Node script (ESM project, so use .cjs extension) to convert each post body and regenerate the .astro files with proper <p>/<h2>/<h3>/<ul> tags. Deployed.
- ALSO: scoped `<style>` in an Astro layout does NOT apply to slot content from the parent page (parent content carries parent scope). Must use `<style is:global>` for typography styles on slot content. (Pit Row BlogPost.astro uses is:global — works.)
- LESSON: When writing Astro pages with large content blocks, either write HTML directly or convert markdown via marked. Never put raw markdown inside a component slot expecting it to render.
