## PS note — BASE64 GARBLING FIX (2026-08-10 10:18) ✅
- **Bug:** llama3.1 sometimes wraps the signature (and anything after it) in a `MIME-Version`/`Content-Type`/`Content-Transfer-Encoding: base64` block. The PS note then showed up as garbled base64 text in the draft. Alec had already sent some emails with the garbled PS (can't unsend).
- **ROOT CAUSE (found 10:32):** NOT the base64 itself — a greedy regex bug. `re.match(r"SUBJECT:\s*(.+)\n\n?(.*)", raw, re.S)` — the `(.+)` with `re.S` matched greedily to the LAST `\n\n`, swallowing the whole email body into the subject group. So `clean_body()` only ever received a ~60-char fragment (just the signature remnant) and never saw the base64 blob to decode it.
- **Fix (2 parts):**
  1. `clean_body()` in `agents/iris_real.py` — decodes base64 MIME blobs, strips MIME headers, strips any model-generated P.S. (avoids duplicates).
  2. **Regex fix:** `SUBJECT:\s*([^\n]+)\n\s*\n?(.*)` — captures subject as only the first line, so the body group correctly captures everything after. This was the actual fix.
- **Verified:** New drafts (Net Assets Corp, The Keyes Company) render clean signature + clean industry-matched PS. Compiles OK.
- **Lesson:** Always verify the RENDERED draft body (not just that a draft was created) before sending. The model's base64 quirk is intermittent. Also: greedy regex with `re.S` is a footgun — always anchor subject capture to the first line.
